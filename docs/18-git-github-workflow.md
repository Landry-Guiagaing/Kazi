# Kazi — Git & GitHub Workflow

## Repository
Nom recommandé : `kazi`.

## Branches
`main`, `feature/*`, `fix/*`, `docs/*`.

## Workflow
Issue → Branch → Development → Checks → Commit → Push → Pull Request → Review → Merge.

## Commit initial
`chore(init): initialize Kazi project`

## Ne jamais committer
node_modules, .next, secrets, fichiers temporaires.

## Issues
Découper les tâches : KAZI-001 setup, KAZI-002 header, KAZI-003 hero, etc.

Même en solo, les PR peuvent servir de contrôle qualité.
